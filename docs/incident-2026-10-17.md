# Workers quota exhaustion, 17 October 2026

The Workers Free account exhausted its 100,000 daily requests. The dashboard
showed 560,737 requests today; bingenz-web-static showed 560,210 invocations
over the preceding 24 hours. These are different time windows.

Security Analytics showed about 599,390 incoming requests, almost all GET,
HTTP/2 and claiming Chrome/Windows. One source sent about 17,070 requests;
sampled requests repeatedly targeted `/` in the same second. This is consistent
with automated flooding, but does not establish the identity or intent of the
sender. Statistics based on sampled analytics are approximate.

## Applied mitigation

The following zone-level rules are managed in the Cloudflare dashboard, not by
Wrangler. Do not remove them through a Worker deployment.

- Custom rule `Protect homepage from automated floods`, ID
  `0b7a2b2b37584f4a8df8283f9a4de4ba`: Managed Challenge for GET/HEAD to `/` or
  `/index.html` on bingenz.com and www.bingenz.com, excluding `cf.client.bot`.
- Rate rule `Limit repeated homepage requests per IP`, ID
  `7b881ffccc6b4fb6b64122362f6eac4e`: paths `/` and `/index.html`, count by IP,
  20 requests per 10 seconds, Block for 10 seconds.

Neither rule matches the SePay webhook or customer APIs. The homepage challenge
is an incident mitigation: review its challenge solve rate and customer impact
before deciding to narrow or remove it. Do not block entire countries or cloud
providers solely on these statistics.

## Asset routing

All three Wrangler configurations now allow only an explicit list of public
assets to bypass the Worker. Every other path retains Worker processing,
including admin HTML aliases, customer access, checkout, API and private runtime
routes. Keep this list explicit when adding public files; never exempt private
shells or reserved paths merely because they have a static file extension.

`tests/asset-routing.test.mjs` exercises the real Miniflare asset router using
the production configuration and actual Worker, with a test-only response
marker. It verifies public requests skip compute and protected requests still
reach Worker checks. Existing commerce tests cover checkout, payment signatures,
entitlement validation and private R2 access using isolated fixtures.

## Recovery and rollback

Serving public assets without invoking a Worker can restore public files even
while the Free quota is exhausted. It cannot reset the account quota. Dynamic
requests on every Worker in this account remain subject to that quota until
00:00 UTC (07:00 Vietnam time) or an approved paid-plan upgrade.

The previous production Worker version was
`40b426cd-1eba-4a55-923b-7a8fefdfad8d`. Roll back only if routing verification
finds a regression; rollback reintroduces compute use for all public requests.
Worker rollback does not roll back databases, buckets or zone WAF rules.

For live verification use low-volume reads: public JavaScript/SVG should return
200; a command-line homepage request should be challenged; unauthenticated
protected paths must never expose private content. A challenge response is not
a Worker quota failure. Do not generate production load to test rate limits.
